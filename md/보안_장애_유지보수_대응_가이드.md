# 부동산 웹사이트 보안·장애·유지보수 대응 가이드

> 목표: 문제를 예방하고, 발생한 문제를 빠르게 탐지·차단·복구하며, 같은 문제가 반복되지 않도록 시스템과 운영 방식을 개선한다.

## 1. 프로젝트의 핵심 성공 기준

이 프로젝트는 기능 수보다 다음 능력을 우선한다.

- **예방:** 최소 권한, 안전한 기본값, 자동 테스트, 검토 절차
- **탐지:** 로그, 지표, 추적 정보, 이상 행동 알림
- **차단:** 공격 경로와 장애 확산을 신속하게 제한
- **복구:** 롤백, 백업 복원, 안전한 재배포
- **학습:** 근본 원인 분석과 재발 방지 테스트
- **유지보수:** 작고 되돌릴 수 있는 변경, 명확한 문서와 책임

```text
예방 -> 탐지 -> 분류 -> 차단 -> 복구 -> 원인 분석 -> 재발 방지
```

## 2. 안전한 장애·보안 훈련 원칙

- 공격과 장애 주입은 격리된 개발 또는 스테이징 환경에서만 수행한다.
- 외부 서비스, 실제 사용자, 허가받지 않은 네트워크를 대상으로 시험하지 않는다.
- 실제 개인정보와 운영용 인증정보를 훈련 데이터로 사용하지 않는다.
- 훈련 전에 중단 조건, 복구 방법, 담당자를 정한다.
- 백업을 만들었다면 훈련 전에 실제 복원 가능 여부를 확인한다.
- 모든 훈련 결과를 자동 테스트, 알림 규칙, 런북에 반영한다.

## 3. 장애 심각도와 대응 목표

| 등급  | 예시                                                                |    최초 확인 | 목표 행동                                         |
| ----- | ------------------------------------------------------------------- | -----------: | ------------------------------------------------- |
| SEV-1 | 전체 서비스 중단, 개인정보 유출 의심, 관리자 계정 탈취, 데이터 파괴 |     5분 이내 | 즉시 책임자 지정, 확산 차단, 증거 보존, 복구 시작 |
| SEV-2 | 주요 기능 일부 중단, 심각한 지연, 외부 API 장애                     |    15분 이내 | 우회 또는 기능 제한, 원인 분석, 사용자 영향 공지  |
| SEV-3 | 제한적인 오류, 운영 우회가 가능한 결함                              |  업무시간 내 | 작업 등록, 수정 일정 지정, 회귀 테스트 추가       |
| SEV-4 | 개선 요청, 경미한 UI 또는 문서 문제                                 | 계획 주기 내 | 우선순위 평가 후 정기 배포에 포함                 |

위 시간은 운영 약속이 아니라 프로젝트 훈련을 위한 초기 목표다. 실제 운영 수준과 인력에 맞춰 조정한다.

## 4. 문제 발생 후 최초 15분

1. 사건 번호를 만들고 발생 및 탐지 시각을 기록한다.
2. SEV 등급과 현재 사용자 영향을 판단한다.
3. 대응 책임자 한 명을 지정하고 의사결정 창구를 단일화한다.
4. 공격 또는 장애 확산을 막는 가장 안전한 조치를 선택한다.
5. 로그, 감사 기록, 배포 기록을 삭제하지 않고 보존한다.
6. 마지막 배포, 설정 변경, 관리자 작업, 트래픽 변화를 확인한다.
7. 롤백, 읽기 전용 전환, 기능 플래그 차단, 요청 제한 중 하나를 준비한다.
8. 조치와 결과를 시간순으로 계속 기록한다.

## 5. 보안 공격 및 침해 상황

### 5.1 DDoS 또는 대량 트래픽 공격

- 발생 가능 원인: 봇넷 요청, 특정 검색·이미지 URL 집중 호출, 공격자가 만든 대량 연결
- 탐지 징후: 초당 요청 수와 네트워크 사용량 급증, 429·502·503 증가, CPU·메모리·비용 급증
- 예상 영향: 서비스 접속 불가, 정상 사용자 차단, 외부 API 및 클라우드 비용 증가
- 즉시 대응: CDN·WAF·요청 제한 강화, 공격 경로 임시 차단, 정적 점검 화면 전환, 인프라 제공자 지원 요청
- 예방·훈련: 요청 제한, 캐시, 자동 확장 한도, 비용 경고, 스테이징 부하 시험, 비상 차단 절차 검증

### 5.2 로그인 무차별 대입과 크리덴셜 스터핑

- 발생 가능 원인: 유출된 계정 목록 재사용, 자동화된 비밀번호 대입
- 탐지 징후: 여러 계정에 대한 반복 실패, 동일 IP·기기에서 대량 로그인, 로그인 성공 후 즉시 정보 변경
- 예상 영향: 사용자 또는 중개사 계정 탈취, 매물 조작, 개인정보 열람
- 즉시 대응: 요청 제한과 추가 인증 적용, 의심 세션 종료, 영향 계정 비밀번호 재설정, 로그인 기록 보존
- 예방·훈련: MFA, 강한 비밀번호 정책, 유출 비밀번호 차단, 기기·위치 이상 탐지, 로그인 공격 시뮬레이션

### 5.3 계정 탈취와 세션 도용

- 발생 가능 원인: 피싱, 세션 토큰 유출, 공용 기기 미로그아웃, 악성 브라우저 확장
- 탐지 징후: 새로운 지역·기기 로그인, 이메일·전화번호 변경, 매물 가격과 계좌 정보의 갑작스러운 수정
- 예상 영향: 사기성 매물 게시, 문의 정보 유출, 관리자 권한 악용
- 즉시 대응: 모든 세션 폐기, 계정 잠금, 본인 확인, 변경 사항 복구, 관련 토큰과 인증정보 교체
- 예방·훈련: 짧은 세션 수명, 보안 쿠키, 중요 변경 재인증, MFA, 세션 목록과 원격 로그아웃

### 5.4 권한 검증 실패와 IDOR

- 발생 가능 원인: URL의 매물·문의 ID만 바꾸면 다른 사용자의 데이터가 조회되거나 수정되는 결함
- 탐지 징후: 소유자가 아닌 계정의 조회·수정 로그, 연속적인 ID 탐색, 권한 오류가 없는 비정상 API 호출
- 예상 영향: 타인 매물 수정, 문의자 개인정보 노출, 관리자 기능 오용
- 즉시 대응: 취약 API 중단, 서버측 소유권 검사 추가, 접근 로그로 영향 범위 조사, 노출된 세션 폐기
- 예방·훈련: 모든 요청의 객체 단위 권한 검사, 역할별 통합 테스트, 거부 로그와 경고

### 5.5 SQL 삽입

- 발생 가능 원인: 검색어나 정렬 조건을 문자열로 직접 쿼리에 연결
- 탐지 징후: 비정상 SQL 오류, 검색 파라미터에 특수 패턴 반복, 데이터베이스 부하와 대량 조회 증가
- 예상 영향: 매물·사용자 데이터 열람 또는 변경, 데이터베이스 장애
- 즉시 대응: 취약 입력 경로 차단, 애플리케이션 또는 WAF 규칙 적용, DB 계정과 비밀정보 교체 검토, 로그 보존
- 예방·훈련: 매개변수 쿼리와 ORM 사용, DB 최소 권한, 입력 스키마 검증, 보안 회귀 테스트

### 5.6 저장형 또는 반사형 XSS

- 발생 가능 원인: 매물 설명, 중개사 소개, 문의 내용이 출력 시 안전하게 처리되지 않음
- 탐지 징후: 페이지에서 예상하지 않은 스크립트 실행, 특정 매물 접근 후 세션 이상, CSP 위반 보고
- 예상 영향: 세션 탈취, 악성 사이트 이동, 관리자 화면 공격
- 즉시 대응: 문제 필드와 페이지 비활성화, 악성 데이터 격리, 세션 폐기, CSP 강화, 영향 사용자 조사
- 예방·훈련: 출력 인코딩, HTML 허용 목록, 보안 쿠키, CSP, 위험 입력 자동 테스트

### 5.7 CSRF

- 발생 가능 원인: 로그인된 사용자가 공격자 페이지를 열었을 때 의도하지 않은 매물 수정 요청이 전송됨
- 탐지 징후: 정상 세션에서 사용자 기억에 없는 변경, 외부 출처에서 온 상태 변경 요청
- 예상 영향: 매물 삭제·가격 변경, 계정 설정 수정
- 즉시 대응: 취약 상태 변경 API 차단, 의심 세션 폐기, 변경 이력 복구
- 예방·훈련: CSRF 토큰, SameSite 쿠키, Origin 검증, GET 요청의 상태 변경 금지

### 5.8 악성 파일 업로드

- 발생 가능 원인: 실행 파일 또는 스크립트를 이미지로 위장, 압축 폭탄, 초대형 이미지 업로드
- 탐지 징후: 확장자와 MIME 불일치, 이미지 처리 실패, 저장 공간·CPU 급증, 비정상 파일 접근
- 예상 영향: 악성코드 배포, 서버 자원 고갈, 저장소 비용 증가
- 즉시 대응: 파일 격리, 다운로드 중단, 업로드 기능 제한, 관련 요청과 계정 조사
- 예방·훈련: 파일 형식·크기·해상도 제한, 재인코딩, 악성코드 검사, 실행 불가능한 별도 저장소

### 5.9 API 키와 비밀정보 노출

- 발생 가능 원인: Git 저장소 커밋, 프론트엔드 번들 포함, 로그 출력, 잘못 공개된 환경 설정
- 탐지 징후: 비정상 API 사용량, 알 수 없는 위치의 접근, 비밀정보 검사 경고
- 예상 영향: 지도·문자 API 비용 증가, DB 접근, 사용자 데이터 유출
- 즉시 대응: 노출된 키 폐기와 교체, 서비스별 접근 기록 확인, 권한 축소, 캐시와 배포본에서 제거
- 예방·훈련: 비밀 저장소, 커밋 전 검사, 짧은 수명 자격증명, 키별 사용 범위와 비용 제한

### 5.10 봇, 스크래핑과 API 남용

- 발생 가능 원인: 매물 정보 대량 수집, 경쟁 서비스 복제, 검색 API 반복 호출
- 탐지 징후: 일정한 간격의 페이지 순회, 비정상 User-Agent, 특정 계정·IP의 과도한 페이지네이션
- 예상 영향: 성능 저하, 비용 증가, 매물 데이터 무단 수집
- 즉시 대응: 속도 제한, 봇 규칙, 의심 토큰 차단, 무거운 검색 기능 임시 제한
- 예방·훈련: 페이지 크기 제한, 캐시, 행위 기반 탐지, API 사용량 경고, 공개 데이터 범위 최소화

### 5.11 공급망과 의존성 침해

- 발생 가능 원인: 악성 또는 탈취된 패키지, 취약한 CI 도구, 위조된 빌드 산출물
- 탐지 징후: 설치 과정의 외부 통신, 예상하지 않은 파일 변경, 보안 경고와 해시 불일치
- 예상 영향: 서버 장악, 비밀정보 유출, 사용자에게 악성 코드 전달
- 즉시 대응: 배포 중단, 의심 버전 격리, 자격증명 교체, 신뢰 가능한 버전으로 재빌드
- 예방·훈련: 잠금 파일, 승인된 저장소, 의존성·라이선스 검사, SBOM, 재현 가능한 빌드

### 5.12 관리자 계정 악용과 내부자 위험

- 발생 가능 원인: 관리자 계정 탈취, 과도한 권한, 사회공학, 고의 또는 실수
- 탐지 징후: 대량 승인·삭제·내보내기, 업무시간 외 작업, 감사 로그 중단
- 예상 영향: 허위 매물 게시, 개인정보 유출, 정상 매물 삭제
- 즉시 대응: 관리자 권한 회수, 세션 폐기, 이중 승인 전환, 변경 복구, 감사 기록 보존
- 예방·훈련: 관리자 MFA, 최소 권한, 중요 작업 이중 승인, 변경 사유 필수, 정기 권한 검토

### 5.13 랜섬웨어 또는 대량 데이터 파괴

- 발생 가능 원인: 서버·관리자 계정 침해, 악성 배포, 백업 계정까지 공유된 권한
- 탐지 징후: 대량 파일 변경·삭제, 테이블 삭제, 백업 실패, 몸값 요구 메시지
- 예상 영향: 서비스 장기 중단, 데이터 손실, 개인정보 사고
- 즉시 대응: 영향 시스템 네트워크 격리, 쓰기 중단, 증거 보존, 자격증명 교체, 검증된 백업 복원
- 예방·훈련: 변경 불가능한 별도 백업, 복원 훈련, 네트워크 분리, 삭제 지연, 대량 변경 경고

### 5.14 개인정보 유출

- 발생 가능 원인: 공개 저장소, 권한 오류, 로그·엑셀 내보내기, 공격자 침입
- 탐지 징후: 대량 조회·다운로드, 공개 버킷 경고, 개인정보가 포함된 오류 로그
- 예상 영향: 사용자 피해, 법적·계약상 대응, 신뢰도 하락
- 즉시 대응: 노출 경로 차단, 증거와 영향 범위 보존, 관련 자격증명 교체, 내부 사고 대응 절차 개시
- 예방·훈련: 수집 최소화, 암호화, 마스킹, 다운로드 통제, 보존 기간과 삭제 정책

## 6. 서비스 장애와 성능 상황

- 예방·훈련: 메모리 지표, 준비·생존 검사, 자원 제한, 장시간 부하 시험

## 9. 측정할 핵심 지표

- **MTTD:** 문제 발생부터 탐지까지 걸린 시간
- **MTTA:** 경고 발생부터 담당자가 대응을 시작하기까지 걸린 시간
- **MTTR:** 탐지 후 정상 복구까지 걸린 시간
- **변경 실패율:** 배포가 장애, 긴급 수정, 롤백으로 이어진 비율
- **복원 성공률:** 백업을 실제로 복원하고 검증한 비율
- **보안 차단 시간:** 공격 징후 탐지부터 확산 제한까지 걸린 시간
- **재발률:** 이미 해결한 유형의 문제가 다시 발생한 비율
- **경고 정확도:** 실제 행동이 필요했던 경고의 비율

## 10. 권장 훈련 순서

처음부터 DDoS나 침해 사고를 크게 재현하지 않고, 복구 가능한 작은 상황부터 진행한다.

1. 잘못된 배포 후 롤백
2. 외부 지도 API 타임아웃
3. 이미지 저장소 오류와 기본 이미지 전환
4. DB 느린 쿼리와 검색 기능 제한
5. 관리자 오삭제와 소프트 삭제 복원
6. 비밀키 노출 가정과 키 교체
7. 계정 탈취 의심과 전체 세션 폐기
8. 백업 데이터로 별도 환경 복원
9. 트래픽 급증과 요청 제한
10. 격리 환경의 DDoS 유사 부하와 비상 모드 전환

## 12. 사건 종료 조건

- 사용자에게 영향을 준 기능이 정상화되었다.
- 공격 또는 장애가 더 확산되지 않는다.
- 데이터 정합성과 백업 상태를 확인했다.
- 임시 조치에 만료 시점과 담당자가 지정되었다.
- 근본 원인과 시간순 기록이 문서화되었다.
- 재발 방지 작업과 자동 테스트가 등록되었다.
- 경고와 런북이 실제 사건에서 발견한 문제를 반영했다.

다음 작업은 위 시나리오 중 `잘못된 배포`, `관리자 오삭제`, `계정 탈취 의심` 세 가지를 선택하여 스테이징용 훈련 절차서로 구체화하는 것이다.
