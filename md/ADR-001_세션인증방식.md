# ADR-001 서버 측 불투명 세션 인증

## 1. 결정

이 서비스의 브라우저 인증은 **서버 측 불투명 세션**을 사용한다.

- 브라우저에는 암호학적으로 안전한 무작위 세션 식별자만 쿠키로 전달한다.
- 데이터베이스와 Redis에는 원본 세션 식별자가 아니라 SHA-256 해시만 저장한다.
- PostgreSQL의 `sessions`가 세션 수명과 폐기 이력의 기준이며 Redis는 빠른 조회용 캐시로 사용한다.
- 운영에서는 웹과 API를 같은 공개 호스트 아래 경로로 라우팅한다.
- 운영 쿠키 이름은 `__Host-re.sid`로 하고 `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`를 적용하며 `Domain`은 지정하지 않는다.
- 로컬 HTTP 개발에서는 `re.sid`를 사용한다. 로컬 예외 설정이 스테이징·운영으로 전달되지 않도록 환경 검증을 둔다.
- 인증 토큰은 URL, HTML, `localStorage`, `sessionStorage`, 로그에 기록하지 않는다.

## 2. 선택 이유

- 관리자 제재, 비밀번호 변경, 계정 탈취 의심 시 세션을 즉시 폐기할 수 있다.
- JWT 블랙리스트나 짧은 액세스 토큰·긴 리프레시 토큰 조합보다 초기 운영 복잡도가 낮다.
- 세션 목록, 기기별 로그아웃, 절대·유휴 만료를 서버에서 일관되게 제어할 수 있다.
- 역할 변경 시 기존 세션을 폐기하고 새 식별자를 발급하여 권한 상승 후 세션 고정 위험을 줄일 수 있다.

## 3. 세션 수명주기

1. 사용자가 이메일과 비밀번호를 제출한다.
2. API는 정규화한 이메일로 계정을 찾고 Argon2id 해시를 검증한다.
3. 성공하면 기존 익명 상태를 승계하지 않고 256비트 이상의 새 세션 식별자와 CSRF 비밀값을 생성한다.
4. 원본 세션 식별자는 쿠키로 한 번만 전달하고 서버에는 해시만 저장한다.
5. 요청마다 폐기 여부, 절대 만료, 유휴 만료, 사용자 상태를 확인한다.
6. 로그아웃, 비밀번호 변경, 권한 변경, 계정 정지, 탈취 의심 시 관련 세션을 폐기한다.

초기 만료 정책:

- 일반 사용자·중개사: 유휴 30분, 절대 12시간
- 관리자: 유휴 15분, 절대 8시간
- 로그인 유지 기능: MVP 제외
- `last_seen_at` 갱신: 데이터베이스 쓰기 폭증을 막기 위해 5분 단위로 제한

## 4. 비밀번호 정책

- Argon2id PHC 문자열을 `password_hash`에 저장한다.
- 초기 목표값은 메모리 64 MiB, 반복 3회, 병렬도 1이며 실제 서버에서 로그인 지연을 측정해 조정한다.
- 최소 12자, 최대 128자를 허용하고 임의의 조합 규칙이나 주기적 강제 변경은 적용하지 않는다.
- 유출 비밀번호 차단과 관리자 MFA는 실제 공개 전 필수 작업이다.
- 로그인 성공·실패 응답은 계정 존재 여부를 드러내지 않는 동일한 메시지를 사용한다.
- IP와 계정 기준 요청 제한, 점진적 지연, 일시 잠금을 함께 적용한다.

## 5. CSRF와 브라우저 방어

- 상태 변경은 `POST`, `PUT`, `PATCH`, `DELETE`만 사용한다.
- 세션에 결합된 동기화 CSRF 토큰을 발급하고 `X-CSRF-Token` 헤더로 검증한다.
- `Origin` 또는 `Referer`와 `Sec-Fetch-Site`를 추가 검증한다.
- JSON 요청만 허용하고 단순 폼 콘텐츠 유형을 받지 않는다.
- `SameSite`는 보조 방어이며 CSRF 토큰을 대체하지 않는다.
- 세션을 발급하거나 포함하는 응답에는 `Cache-Control: no-store`를 적용한다.

## 6. 권한 관리

- 역할은 `USER`, `AGENT`, `ADMIN` 세 종류로 시작한다.
- 인증 Guard와 역할 Guard를 분리한다.
- 역할만 확인하지 않고 매물·문의 등 객체의 소유권을 매 요청에서 검사한다.
- 관리자 작업, 역할 변경, 제재, 로그인 이상 징후는 감사 로그에 기록한다.
- 관리자 MFA는 TOTP 또는 WebAuthn 중 하나를 별도 ADR로 확정한다.

## 7. 선택하지 않은 대안

### 브라우저 저장소의 JWT

XSS 발생 시 토큰을 직접 탈취할 수 있고 즉시 폐기와 기기별 세션 관리가 어렵기 때문에 사용하지 않는다.

### HttpOnly 쿠키의 완전 무상태 JWT

서버 저장소 조회를 줄일 수 있지만 역할 변경과 계정 정지를 즉시 반영하려면 별도의 폐기 목록이 필요하여 현재 규모에서는 이점이 작다.

### 외부 인증 서비스 단독 의존

초기 구현은 빨라질 수 있지만 중개사·관리자 승인과 보안 훈련에 필요한 세션·감사 제어를 학습하기 어렵다. 향후 소셜 로그인은 계정 연결 기능으로 추가할 수 있다.

## 8. 보안 및 운영 영향

- Redis 장애 시 PostgreSQL을 제한적으로 조회하는 저하 모드를 둘 수 있다.
- PostgreSQL 장애 시 새 로그인과 세션 검증을 실패 안전 방식으로 차단한다.
- 세션 해시와 감사 로그에도 접근 권한과 보존 기간을 적용한다.
- 원본 IP 대신 별도 비밀키를 사용하는 HMAC을 저장하여 개인정보 노출과 단순 역추적을 줄인다.
- 비밀키 교체 시 기존 HMAC과 새 HMAC을 구분할 키 버전이 필요하다.

## 8.1 구현 상태

2026-09-04에 회원가입·이메일 확인·로그인·현재 사용자 확인·CSRF 교체·로그아웃의 인증 세로 기능을 구현했다. Argon2id, 해시 세션 저장, PostgreSQL 기준·Redis 캐시, 절대·유휴 만료, CSRF와 Origin 검사, 로그인 실패 잠금, 역할 Guard, 감사 로그가 적용됐다. 가입·확인·로그인에는 HMAC 지문과 Redis 원자 카운터를 사용하는 IP·이메일 요청 제한도 적용했다. 운영 메일 발송, 관리자 MFA, 비밀키 버전 교체는 후속 작업이다.

## 9. 롤백 및 변경 방법

인증 전송 방식을 바꾸더라도 컨트롤러는 `AuthenticatedPrincipal`만 사용하도록 경계를 둔다. OAuth 또는 토큰 방식을 추가할 때 인증 어댑터와 Guard를 교체하고 도메인 권한 로직은 유지한다. 변경 시 새 ADR과 세션 전환·강제 로그아웃 계획을 작성한다.
