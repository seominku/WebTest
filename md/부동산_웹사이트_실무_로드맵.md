# 부동산 광고 및 매물 웹사이트 실무 로드맵

> 목표: 부동산 매물 서비스를 기획, 개발, 배포, 운영하고 실제 실무에서 발생하는 장애, 보안, 데이터 품질 문제를 재현하여 해결하는 전 과정을 연습한다.

## 1. 프로젝트 운영 원칙

- 초기에는 가상 매물과 테스트 계정만 사용한다.
- 개발, 스테이징, 운영 환경을 분리한다.
- 모든 기능은 화면, API, 데이터베이스, 권한, 테스트, 로그를 함께 완성한다.
- 가격, 게시 상태, 관리자 조치는 변경 이력을 남긴다.
- 장애 훈련은 운영 데이터가 없는 스테이징 환경에서 먼저 진행한다.
- 실제 공개 전 개인정보, 광고 표시, 중개사 정보, 지도 및 이미지 데이터 이용 조건을 별도로 검토한다.

## 2. 전체 진행 순서

```text
요구사항 정의
-> 화면 및 업무 흐름 설계
-> 기술 구조와 데이터 모델 결정
-> 개발 환경 구축
-> MVP 구현
-> 자동 테스트와 보안 점검
-> 스테이징 배포
-> 모니터링과 백업 구축
-> 장애 및 위험 상황 훈련
-> 성능 개선
-> 실제 공개 여부 판단
```

## 3. 단계별 로드맵

### 1단계. 프로젝트 범위 정의

결정할 항목:

- 사용자 유형: 일반 사용자, 중개사, 관리자
- 매물 유형: 아파트, 주택, 오피스텔, 상가 등
- 거래 유형: 매매, 전세, 월세
- 초기 서비스 지역
- 허위 매물 신고와 검수 방식
- 실제 공개 여부와 개인정보 처리 범위

산출물:

- 1페이지 프로젝트 기획서
- MVP 기능 목록
- 제외 기능 목록
- 용어 사전

완료 조건: 누가 어떤 문제를 해결하기 위해 서비스를 사용하는지 한 문장으로 설명할 수 있다.

### 2단계. 사용자 흐름과 화면 설계

핵심 업무 흐름:

```text
중개사 매물 등록
-> 관리자 검수
-> 광고 게시
-> 사용자 검색
-> 상세 확인 및 문의
-> 거래 완료 또는 광고 만료
```

우선 설계할 화면:

- 메인 및 검색 결과
- 지도와 목록 보기
- 매물 상세
- 로그인과 회원가입
- 중개사 매물 관리
- 관리자 검수 및 신고 처리
- 찜, 문의, 오류, 권한 없음, 점검 중 화면

완료 조건: 사용자, 중개사, 관리자의 대표 업무를 화면 흐름으로 끝까지 따라갈 수 있다.

### 3단계. 기술 구조 결정

초기 권장 구조:

- 프론트엔드: Next.js, TypeScript
- 백엔드: Next.js 서버 기능 또는 NestJS
- 데이터베이스: PostgreSQL
- 데이터 접근: Prisma
- 이미지: S3 호환 오브젝트 저장소
- 테스트: Vitest, Playwright
- 배포: Docker 기반
- 환경: 개발, 스테이징, 운영 분리

처음에는 관리하기 쉬운 단일 애플리케이션으로 시작하고, 실제 병목이 확인될 때 검색 서버나 개별 서비스를 분리한다.

완료 조건: 요청이 브라우저에서 데이터베이스와 이미지 저장소까지 이동하는 경로를 설명할 수 있다.

### 4단계. 데이터 모델 설계

주요 데이터:

- 사용자, 역할, 로그인 세션
- 중개사무소와 중개사
- 매물, 주소, 위치, 가격, 옵션
- 매물 이미지와 대표 이미지
- 광고 상태와 게시 기간
- 찜, 문의, 신고
- 관리자 검수 및 제재 기록
- 매물과 가격 변경 이력
- 보안 및 감사 로그

중요한 설계 원칙:

- 매물 삭제는 우선 소프트 삭제로 처리한다.
- 가격은 정수 단위와 통화 기준을 명확히 한다.
- 주소 공개 범위를 구분한다.
- 중복 매물을 식별할 기준을 둔다.
- 누가 언제 무엇을 바꿨는지 기록한다.

완료 조건: ERD와 핵심 테이블 정의가 있고, 매물 상태 변화가 데이터로 표현된다.

### 5단계. 개발 및 배포 기반 구축

- Git 브랜치와 코드 리뷰 규칙
- 이슈 및 작업 단위 작성 규칙
- 환경변수와 비밀정보 관리
- 코드 스타일, 정적 분석, 자동 테스트
- 데이터베이스 마이그레이션
- 시드 데이터 생성
- CI/CD와 배포 실패 시 롤백 절차

완료 조건: 새 코드가 자동 검사와 테스트를 통과해야 스테이징에 배포된다.

### 6단계. MVP 세로 단위 구현

권장 구현 순서:

1. 로그인과 역할별 권한
2. 매물 등록, 수정, 조회
3. 이미지 업로드
4. 검색, 정렬, 필터
5. 관리자 승인과 게시 상태
6. 찜과 문의
7. 신고와 계정 제재
8. 변경 이력과 감사 로그
9. 반응형 화면과 접근성
10. 검색엔진 최적화 기본 설정

각 기능은 다음 항목을 함께 완료한다.

- 사용자 화면
- 서버 API
- 데이터 저장
- 입력값 검증
- 권한 검사
- 오류 처리와 로그
- 단위 및 통합 테스트

완료 조건: 가상 중개사가 매물을 등록하고 관리자가 승인한 뒤 일반 사용자가 검색하고 문의할 수 있다.

### 7단계. 테스트와 보안 점검

정상 동작 외에 다음 오용 사례를 시험한다.

- 다른 중개사의 매물 수정 요청
- SQL 삽입 및 XSS 입력
- 실행 파일을 이미지로 위장한 업로드
- 너무 큰 이미지 또는 대량 업로드
- 로그인 무차별 대입
- 동일 문의 반복 전송
- 음수 또는 비정상적으로 큰 가격
- 삭제된 매물의 직접 주소 접근
- 일반 사용자의 관리자 API 호출
- 개인정보가 로그나 오류 화면에 노출되는 상황

완료 조건: 핵심 권한 및 입력 검증 테스트가 자동화되고 발견된 취약점의 재현 테스트가 남아 있다.

### 8단계. 스테이징 배포와 운영 준비

- 서비스 및 API 상태 확인
- 오류 추적과 경고
- 느린 요청 및 데이터베이스 쿼리 감시
- 트래픽, 저장 공간, 외부 API 비용 감시
- 데이터베이스 자동 백업
- 백업 복구 연습
- 배포 롤백
- 관리자 작업 감사 로그
- 장애 대응 문서와 담당 역할

완료 조건: 장애를 발견할 수 있고, 이전 버전과 백업 데이터로 실제 복구할 수 있다.

### 9단계. 장애 및 위험 상황 훈련

| 훈련 상황           | 확인할 문제                 | 해결 목표                           |
| ------------------- | --------------------------- | ----------------------------------- |
| 잘못된 코드 배포    | 오류율 증가, 핵심 기능 실패 | 배포 중단, 롤백, 재발 방지 테스트   |
| 데이터베이스 지연   | 검색과 상세 화면 지연       | 병목 쿼리 확인, 인덱스, 부하 제한   |
| 지도 API 한도 초과  | 지도 또는 주소 검색 실패    | 캐시, 사용량 경고, 대체 화면        |
| 이미지 저장소 장애  | 업로드와 이미지 표시 실패   | 재시도, 기본 이미지, 복구 작업      |
| 허위 매물 대량 등록 | 신고 급증, 서비스 신뢰 하락 | 승인 절차, 자동 탐지, 계정 제한     |
| 계정 탈취 의심      | 비정상 로그인 및 수정       | 세션 종료, 인증정보 변경, 감사 조사 |
| 관리자 오삭제       | 정상 매물 비공개 또는 삭제  | 소프트 삭제, 이력 확인, 복구        |
| 비밀키 노출         | 외부 서비스 악용 가능성     | 키 폐기와 교체, 접근 이력 확인      |
| 트래픽 급증         | 서버 과부하와 비용 증가     | 캐시, 요청 제한, 병목 분석          |
| 데이터 손상         | 매물 또는 사용자 정보 유실  | 백업 복원, 손실 범위와 원인 확인    |
| DB 구조 불일치      | 배포 후 서버 실행 실패      | 호환 마이그레이션, 단계적 배포      |
| 개인정보 로그 기록  | 민감정보 유출 위험          | 로그 제거, 마스킹, 접근 조사        |

완료 조건: 각 시나리오에 대해 탐지, 대응, 복구, 회고 기록이 존재한다.

### 10단계. 성능 개선과 공개 판단

- 실제 측정 결과를 기준으로 느린 구간을 개선한다.
- 이미지 크기와 전송 비용을 최적화한다.
- 자주 조회되는 검색 결과에 캐시를 적용한다.
- 접근성, 모바일 사용성, SEO를 재점검한다.
- 법률, 개인정보, 외부 API 이용 조건을 검토한다.
- 운영 비용과 담당 가능 시간을 계산한다.

완료 조건: 공개 체크리스트의 모든 필수 항목을 통과하고 운영 및 중단 기준이 문서화되어 있다.
