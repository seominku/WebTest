# 브라우저 사용자 흐름 점검

## 범위와 방법

로컬 Docker 환경의 Chrome에서 MCP computer-use로 고객·중개사·관리자 화면을 직접 조작했다. 기존 로컬 시드 계정과 가상 매물만 사용했으며 실제 고객 계정이나 실제 방문 일정은 사용하지 않았다. API 검사만으로는 발견하기 어려운 화면 오류, 역할 간 전달, 저장 후 표시를 확인하기 위한 작업이다.

## 발견 및 수정

### 지도 오류가 목록 전체를 가리는 문제

- 브라우저 로그에서 `L is not defined`, `markerClusterGroup is not a function` 확인. 지도 본체와 마커 묶음 스크립트를 동시에 로드해 실행 순서가 뒤바뀔 수 있었다.
- `listing-map.tsx`: 지도 본체 준비 후 마커 묶음 스크립트 로드. `onLoad` 대신 재진입에도 호출되는 `onReady` 사용. 실제 함수 존재 검사 및 로드 실패 안내 추가.
- 역할: 마커 묶음은 가까운 매물을 숫자로 묶어 표시하는 기능이다. 지도 본체가 준비된 뒤 실행해야 목록까지 오류 화면으로 바뀌지 않는다.
- 지도 패널의 `APARTMENT`도 기존 한글 유형 표기를 재사용해 `아파트`로 변경했다.

### 업로드 사진이 공개 화면에서 깨지는 문제

- 사진 API는 HTTP 200, `image/webp`를 반환했지만 브라우저에서 이미지 로드가 실패했다.
- API의 `Cross-Origin-Resource-Policy: same-origin`과 다른 포트의 웹 화면에서 보내는 기본 이미지 요청이 충돌했다.
- 목록 카드·상세 갤러리·지도 패널 이미지에 `crossOrigin="anonymous"` 적용. API의 기존 WEB_ORIGIN 허용 설정을 사용해 CORS 이미지 요청으로 읽도록 했다. 전역 보안 헤더나 허용 출처를 완화하지 않았다.
- 수정 후 같은 공개 이미지의 `naturalWidth > 0` 확인, 목록의 깨진 이미지 0개 확인.
- 참고: [MDN 이미지 crossorigin](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img#crossorigin), [MDN CORP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Resource-Policy).

### 게시 변경 후 이전 목록이 남는 현상

- API는 새 게시 매물을 포함해 6건을 반환했지만 웹은 이전 5건을 표시했다.
- `lib/listings.ts`의 목록·상세 서버 조회를 30초 재검증 캐시에서 `cache: "no-store"`로 변경했다.
- 다음 서버 요청마다 게시 여부와 공개 범위를 다시 조회한다. 이미 열린 화면의 자동 실시간 갱신을 의미하지 않으며, API 자체 HTTP 캐시 정책은 이번에 변경하지 않았다.
- 일시 중지 후 목록 이동에서 즉시 5건으로 복귀하고 상세 페이지는 공개 불가 안내를 표시하는 것까지 확인했다.

## 남은 제한과 외부 통신 구분

- Chrome 파일 선택 자동화는 확장의 파일 URL 접근 권한 부족으로 `Not allowed`가 발생했다. 확장 설정은 임의 변경하지 않았다. 이번 사진 업로드는 로컬 샘플 파일을 로컬 API로 전송하고 브라우저 결과를 확인했다. 파일 선택 버튼부터 전송까지의 완전한 브라우저 업로드 흐름은 권한 설정 후 재검증이 필요하다.
- 날짜·시간 자동 채우기는 DOM 값만 바뀌고 앱 입력 상태가 갱신되지 않는 도구 제약이 있었다. 각 날짜·시간 칸에 실제 키 이벤트로 입력하자 정상 저장됐다. 앱 버그로 단정하지 않았다.
- 이번 QA 매물은 좌표가 없으므로 지도에 마커를 임의 생성하지 않았다. 지도는 좌표가 있는 기존 시드 매물로 검사했다. 외부 주소 변환 승인 전 실제 위치 정확도를 보장할 수 없다.
- 지도 CDN·타일 및 주변 시설 조회는 기존 외부 브라우저 통신이다. 이번에 보류 상태를 확인한 것은 주소/우편번호 지오코딩과 외부 경보 전송이며, 사이트 전체의 외부 통신이 전혀 없다는 뜻이 아니다. 주변 시설 데이터의 완전성·운영 여부는 이번 검증 대상이 아니다.
