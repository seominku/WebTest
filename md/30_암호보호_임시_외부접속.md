# 구성과 필요한 이유

1. Cloudflare Quick Tunnel: 이 컴퓨터에서 외부로 터널을 열어 임시 HTTPS 주소를 제공한다. 공유기 포트 포워딩, 방화벽 개방, 유료 도메인 구매나 계정 생성 없이 이번 테스트 연결을 만들었다. 테스트 트래픽과 접속 인증 정보는 Cloudflare 중계 구간을 통과하므로 실제 개인정보를 입력하지 않는다. Quick Tunnel은 개발/시험용이며 SLA가 없다. [공식 안내](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)
2. Caddy: 사이트 앞에서 별도 Basic Auth 암호를 검사한다. bcrypt cost 12 해시를 표준 명령에 stdin으로 생성했고 평문 접속 암호를 Docker 명령 인자로 전달하지 않는다. 웹·API·정적 파일·사진 모두 인증 뒤에 위치한다. 애플리케이션으로 전달할 때 Authorization 헤더를 제거한다. [공식 인증 문서](https://caddyserver.com/docs/caddyfile/directives/basic_auth)
3. 별도 Docker 네트워크와 볼륨: 테스트 DB·Redis 세션·MinIO 사진·ClamAV를 원본과 분리한다. 내부망에는 외부 포트가 없다. Caddy만 이번 실행의 내부망과 입구망 양쪽에 연결하고 `127.0.0.1:4310`만 호스트에 연다. 원본 네트워크에 연결하지 않는다. [Docker 네트워크 구성](https://docs.docker.com/engine/network/)
4. 별도 웹 빌드: 브라우저 API 주소를 `/api/v1`로 빌드하고 서버 내부 조회는 `http://preview-api:4000/api/v1`로 설정한다. 휴대폰의 localhost를 잘못 호출하지 않게 한다. 원본 웹 이미지/컨테이너는 교체하지 않는다.
5. production 인증 설정: 이번 테스트 API만 `APP_ENV=production`, 정확한 HTTPS `WEB_ORIGIN`, `TRUST_PROXY_HOPS=1`을 쓴다. Secure·HttpOnly·SameSite=Lax·`__Host-re.sid` 세션 쿠키와 CSRF를 검증했다. 프록시가 X-Forwarded-For를 덮어쓰기 때문에 IP 위조 헤더를 믿지 않으며, 터널 사용자는 보수적으로 하나의 IP 제한을 공유한다.

검색 제외 헤더와 no-store를 적용했다. 회원 가입/이메일 확인, 진단 health/metrics 및 admin API는 게이트 뒤에서도 404로 차단한다. 관리자 계정은 만들지 않았다. 주소 지오코딩과 외부 경보 전달은 계속 비활성이다. 일반 회원/중개사 테스트 계정 2개만 제공한다.

감독 프로세스가 비정상 종료되었다면 중지 요청 파일만으로 정리가 완료되지는 않는다. 이때는 `.artifacts/preview-status.json`의 실행 ID와 실제 프로세스/라벨을 대조한 뒤 해당 자원만 정리해야 한다. 전체 Docker 정리나 모든 cloudflared 프로세스 종료를 하지 않는다.

다음 실행은 현재 실행의 종료/정리 상태를 확인한 후 `npm.cmd run preview:start`로 새 가상 환경을 만든다. 이 명령은 포그라운드 감독 실행이며, 창을 유지해야 한다. 새 주소·새 암호·새 볼륨이 생성되고 이전 테스트 데이터를 자동으로 복원하지 않는다. 웹 변경 후에는 동일 Dockerfile의 `NEXT_PUBLIC_API_BASE_URL=/api/v1` 빌드 인자로 전용 웹 이미지를 다시 빌드해야 한다. 원본 `.env`를 읽거나 원본 시드 명령을 운영 대상으로 실행하지 않는다.
