# 의존성 보안 관리

## 현재 조치

- Prisma와 `@prisma/client`는 현재 검증된 7.10.0을 유지한다.
- Prisma CLI가 고정한 `deepmerge-ts 7.1.5`는 8.0.2로 교체한다.
- Prisma CLI가 고정한 `mysql2 3.15.3`은 3.24.3으로 교체한다.
- 교체 버전은 루트 `package.json`의 `overrides`와 `package-lock.json`으로 재현한다.
- 로컬과 Docker 설치 도구는 npm 11.19.1로 통일한다. `packageManager`는 기준 버전을 기록하고 `engines.npm`과 `.npmrc`의 `engine-strict=true`는 npm 11.19.1 이상·12 미만만 설치에 사용하도록 검사한다.

`mysql2`는 현재 서비스가 PostgreSQL을 사용하므로 애플리케이션 데이터 경로에서는 실행되지 않는다. 하지만 개발·빌드 의존성 공급망에 포함되므로 제거하지 않고 수정 버전으로 고정한다.

## 검증 명령

1. `npm.cmd --version`: 기준 버전 11.19.1을 확인한다. 다르면 `npm.cmd install --global npm@11.19.1`로 맞춘다.
2. `npm.cmd ci`: 잠금 파일과 동일한 의존성을 깨끗하게 설치한다.
3. `npm.cmd run deps:check`: 전체 의존성 트리의 누락·버전 불일치를 검사한다. 실패를 무시하지 않는다.
4. `npm.cmd run security:audit`: 최신 npm 보안 권고와 비교한다.
5. `npm.cmd run db:validate`: 교체된 설정 병합 라이브러리로 Prisma 설정과 스키마를 읽을 수 있는지 확인한다.
6. `npm.cmd run build`: Prisma Client 생성과 API·Web 프로덕션 빌드를 검사한다.
7. `npm.cmd run test:integration`: PostgreSQL·Redis를 사용하는 실제 저장 흐름을 검사한다.

## 버전 불일치 원인과 수정

기존 npm 11.17.0에서 `npm ls`가 보안 교체 버전을 `invalid`로 표시했다. 처음에는 의도적인 버전 교체의 표시상 예외로 기록했으나, 추가 조사에서 workspace 연결을 지날 때 override가 전파되지 않는 npm 버그가 원인임을 확인했다. 이 버그는 업데이트 시 취약한 원래 버전으로 돌아갈 가능성도 있어 허용 가능한 예외로 취급하지 않는다.

공식 수정은 [npm PR #9671](https://github.com/npm/cli/pull/9671)과 [11.x 반영 PR #9673](https://github.com/npm/cli/pull/9673)에 설명되어 있다. 동일한 프로젝트 트리에서 npm 11.17.0은 실패했고 npm 11.19.1은 두 패키지를 `overridden`으로 인식하며 종료 코드 0을 반환했다. 따라서 앱 라이브러리를 교체하지 않고 npm 도구 버전을 갱신했다.

Docker의 Web·API 빌드 단계와 API 운영 의존성 설치 단계도 npm 11.19.1을 명시적으로 설치한다. Web·API 빌드는 `npm ci` 다음에 `npm ls --all`을 실행해 의존성 불일치가 있으면 실패한다. 운영 이미지의 앱 패키지에는 npm 도구를 새 의존성으로 추가하지 않는다.

## 임시 보안 override 유지 기준

2026-09-05 검증: npm 11.19.1에서 `npm update deepmerge-ts mysql2 --ignore-scripts`와 `npm ci`를 실행한 뒤 두 보안 버전 및 전체 패키지 버전이 유지되었다. 전체 `npm ls --all` 종료 코드 0, npm 보안 감사 0건, Prisma 스키마 검증·생성·로컬 및 Docker 빌드·단위 테스트 7건·사용자 흐름 스모크 테스트가 통과했다. 구버전 npm 11.16.0의 오프라인 설치 dry-run은 `EBADENGINE`으로 차단되었다.

Prisma가 취약점이 수정된 간접 패키지를 공식 포함한 안정 버전을 발표하면 다음 순서로 임시 override를 제거한다.

1. Prisma와 `@prisma/client`를 같은 안정 버전으로 갱신한다.
2. `overrides` 두 항목을 제거하고 잠금 파일을 새로 계산한다.
3. 위 검증 명령과 Docker 빌드를 모두 통과시킨다.
4. `npm ls`에 버전 불일치가 없는지 확인한다.

Prisma 주 버전 다운그레이드나 시험판 업그레이드는 스키마·생성 클라이언트 호환성 검토 없이 적용하지 않는다.

도구 설정을 되돌려야 하면 `packageManager`, `engines.npm`, `.npmrc`, Docker npm 버전 지정과 잠금 파일 메타데이터를 함께 복원한다. 이전 npm 11.17.0에는 위 버그가 있으므로 일상 설치 도구로 되돌리는 것은 피한다. 이번 변경 전 잠금 파일은 로컬 `.artifacts/package-lock.before-npm-fix.json`에 보관되어 있다.
