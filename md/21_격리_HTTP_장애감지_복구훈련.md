# 격리 HTTP 장애 감지·복구 훈련

## 무엇을 검증했는가

기존 단위 테스트는 `fetch` 응답을 코드에서 대체했다. 이번 테스트는 루프백 주소의 임시 포트 4개에 모의 웹·API·Prometheus·Alertmanager HTTP 서버를 띄우고, 운영 점검 도구가 실제 HTTP 요청을 보내도록 했다.

목적은 점검 도구가 실제 연결 중단·응답 지연·응답 오류를 감지하고, 테스트 서비스가 복구되면 정상으로 판정하는지 확인하는 것이다. 실제 Next.js·NestJS·PostgreSQL·Redis·MinIO·ClamAV·Prometheus·Alertmanager를 복제하거나 중단한 훈련은 아니다.

## 실행 방법

프로젝트 루트에서 실행한다. Docker가 켜져 있을 필요는 없다.

```powershell
npm.cmd run test:operations:drill
```

임시 서버는 `127.0.0.1`에만 바인딩하고 운영체제가 빈 포트를 배정한다. 현재 앱의 3000·4000·9090·9093 포트를 테스트 대상으로 지정하지 않는다. 시험 중단·재시작 대상은 이 실행에서 생성한 서버 객체뿐이다. 종료 시 연결과 서버를 닫으며 파일·DB·Docker 볼륨은 생성하지 않는다.

CLI 검증은 실제 `operations-check.mjs`를 별도 Node 프로세스로 실행하며, 네 서비스 포트를 모두 테스트 포트로 덮어쓴다. CLI의 기존 `.env` 읽기 경로는 실행되지만 인증정보를 요청에 넣지 않으며 앱 서버에 요청하지 않는다.

## 검증 시나리오

| 상황 | 장애 상태에서 기대하는 결과 | 복구 방법 |
| --- | --- | --- |
| 초기 정상 | 전체 10항목 통과 | 해당 없음 |
| 모의 웹 리스너 종료 | 웹 항목만 실패 | 같은 테스트 포트에 서버 재시작 |
| 모의 Alertmanager 리스너 종료 | Alertmanager 항목만 실패 | 같은 테스트 포트에 서버 재시작 |
| 의존 서비스 장애 응답 | readiness HTTP 503 감지 | 정상 JSON·HTTP 200 복원 |
| API 연결 강제 종료 | API 관련 4항목 실패 | 연결 종료 동작 해제 |
| 인증 없는 지표 공개 응답 | 지표 보호 2항목 실패 | HTTP 401 복원 |
| 수집·평가 시각 지연 | 지표 수집·경보 규칙 항목 실패 | 최근 시각 응답 복원 |
| 경보 발생 응답 | 경보 규칙 항목 실패 | inactive 응답 복원 |
| 잘못된 JSON | 웹 응답 형식 오류 감지 | 정상 JSON 복원 |
| 리다이렉트 | 웹 실패 및 이동 대상 요청 0건 | 직접 정상 응답 복원 |
| 응답 본문 중단 | 실제 2초 제한 시간으로 웹 실패 | 완전한 응답 복원 |
| 실제 CLI 실행 | 정상 0 → 장애 1 → 복구 0 종료 코드 | 장애 응답 해제 후 재실행 |

모든 장애 시나리오는 실패 항목 목록을 정확히 비교한다. 장애를 해제한 후에는 전체 10개 항목이 다시 통과해야 한다. 테스트의 시간 제한은 2초, 기존 운영 점검 명령은 8초로 유지했다.

## 결과

- 세부 검사 12개 모두 통과했다. Node 테스트 출력에는 상위 테스트 1개를 포함해 총 13개 통과로 표시된다.
- 기존 점검 도구 단위 테스트 15개도 통과했다.
- 2026-09-05 19:09:24 KST 현재 실제 로컬 서버를 읽기 전용으로 재점검한 결과 10개 항목 모두 통과했다.
- 외부 연결 사전 점검에서 주소 지오코딩 승인 보류와 외부 경보 수신 채널 미설정을 확인했다.
- 소스 포맷 검사 통과. 앱 소스와 패키지 의존성을 변경하지 않아 앱 재빌드는 하지 않았다.

## 안전 범위와 남은 검증

실제 고객·계정·매물·사진 데이터, 실행 중인 Docker 서비스, 기존 보안 정책은 변경하지 않았다. 외부 경보나 주소 전송을 활성화하지 않았다. 훈련 응답은 모두 합성 데이터이며 실제 서비스 사고가 아니다.

이 결과는 점검 도구의 감지·복구 판정 검증이다. DB 프로세스 종료 후 연결 풀 회복, 사진 검사 중단 시 재시도, 실제 Prometheus 규칙 평가와 Alertmanager 종단 전달, DB 데이터 복원 성공을 입증하지 않는다. 해당 훈련은 별도의 실제 인프라 격리 환경과 명시적인 대상·정리 절차가 필요하다.
