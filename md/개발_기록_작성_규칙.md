# 개발 작업 기록 작성 규칙

## 1. 목적

이 프로젝트에서 수행하는 개발, 설정, 테스트, 배포, 보안 점검, 장애 훈련, 유지보수 작업을 Markdown으로 기록한다.

기록의 목적은 다음과 같다.

- 언제 무엇을 변경했는지 추적
- 문제 발생 시 변경 이력과 원인 확인
- 롤백과 복구 방법 보존
- 보안에 영향을 준 결정 확인
- 다른 담당자가 작업을 이어받을 수 있는 상태 유지
- 같은 문제가 반복되지 않도록 학습 내용 축적

## 2. 시간 기록 기준

- 시간대: **Asia/Seoul, KST**
- 표기 형식: `YYYY-MM-DD HH:mm:ss KST`
- 모든 새 문서에는 `created_at`을 기록한다.
- 문서를 변경하면 `updated_at`을 갱신한다.
- 작업 로그에는 작업 시작 또는 완료 시각을 초 단위로 기록한다.
- 정확한 시각을 확인할 수 없을 때 임의로 만들지 않고 `시간 확인 필요`라고 기록한다.

## 3. 반드시 기록할 작업

- 소스 코드 생성·수정·삭제
- 패키지 설치·제거·버전 변경
- 데이터베이스 스키마와 마이그레이션
- 환경변수 이름과 설정 구조 변경
- Docker·서버·클라우드 인프라 변경
- 인증·권한·요청 제한 등 보안 변경
- 자동 테스트 추가·수정과 테스트 결과
- 배포, 롤백, 백업, 복원
- 오류·장애·보안 의심 사건 조사
- 중요한 기술 선택과 선택하지 않은 대안
- 운영 절차와 런북 변경

비밀번호, 토큰, API 키, 개인정보는 기록 파일에 절대 적지 않는다.

## 4. 기록 방식

### 작은 작업

`개발_작업_기록.md`에 시간순으로 누적한다.

예시:

```markdown
## 2026-09-04 10:30:00 KST - 로그인 요청 제한 추가

- 작업 유형: 보안
- 목적: 무차별 대입 공격 완화
- 변경 내용: 로그인 API에 IP·계정 기준 요청 제한 적용
- 변경 파일: apps/api/src/auth/...
- 보안 영향: 인증 공격 차단 강화
- 유지보수·롤백: 설정값 복원으로 비활성화 가능
- 검증: 단위 테스트 및 429 응답 확인
- 결과: 완료
- 다음 작업: Redis 장애 시 동작 검증
```

### 중요한 결정 또는 큰 작업

별도 Markdown 문서를 만들고 `개발_작업_기록.md`에서 해당 문서를 연결한다.

별도 문서가 필요한 예:

- 아키텍처 결정
- 인증·권한 설계
- 데이터베이스 모델
- 배포 구조
- 장애 대응 결과 보고서
- 보안 사고 조사 보고서
- 백업 복원 훈련

## 5. 작업 기록 필수 항목

모든 로그 항목에는 가능한 범위에서 다음 내용을 포함한다.

1. 작업 시각
2. 작업 유형
3. 목적
4. 변경 내용
5. 생성·수정·삭제한 파일
6. 보안 영향
7. 운영 및 유지보수 영향
8. 롤백 또는 복구 방법
9. 실행한 검증과 결과
10. 미해결 문제
11. 다음 작업

## 6. 장애 및 보안 사건의 추가 항목

- 사건 심각도
- 발생·탐지·대응·복구 시각
- 사용자 영향
- 영향받은 시스템과 데이터
- 확인된 사실과 아직 확인하지 못한 가정
- 즉시 차단 조치
- 보존한 로그와 증거
- 근본 원인
- 재발 방지 작업과 담당 기한

## 7. 문서 이름 권장 규칙

```text
NN_주제.md
YYYYMMDD-HHMM_장애명_대응기록.md
ADR-NNN_기술결정명.md
```

예:

```text
03_서버_기술스택_선정.md
20260920-1420_DB연결풀고갈_대응기록.md
ADR-002_세션인증방식.md
```

## 8. 완료 기준

개발 작업은 다음 조건을 모두 만족해야 완료로 기록한다.

- 필요한 코드 또는 설정 변경이 끝났다.
- 관련 테스트나 검증을 실행했다.
- 보안과 유지보수 영향을 확인했다.
- 롤백 또는 복구 방법을 알고 있다.
- `개발_작업_기록.md`에 작업 내역과 시간이 기록되었다.
