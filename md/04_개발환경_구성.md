# 부동산 웹사이트 모노레포 및 로컬 개발 환경 구성

## 1. 작업 결과

브랜드명이 정해지기 전까지 `real-estate-platform`을 내부 작업명으로 사용한다. 브랜드명은 패키지 경계와 무관하므로 나중에 변경할 수 있다.

```text
apps/
  web/              Next.js 16 웹 앱
  api/              NestJS 12 API 서버
packages/
  config/           공통 TypeScript 엄격 설정
  db/               Prisma 7 스키마와 클라이언트 생성 코드
  shared/           웹·API 공통 계약
infrastructure/
  docker/           웹·API 이미지 정의
docker-compose.yml  PostgreSQL, Redis, MinIO, 웹, API
```

루트 npm workspaces에서 설치, 개발, 빌드, 검사, 테스트, Prisma 명령을 실행한다.
Git 저장소는 `main` 브랜치로 초기화했다. 첫 커밋은 변경 내용을 검토한 뒤 사용자가 직접 확정할 수 있도록 만들지 않았다.

## 2. 적용한 버전

- Node.js: 24 LTS
- npm: 11
- Next.js: 16.3.4
- React: 19.2.8
- NestJS: 12.0.1
- Prisma: 7.10.0
- PostgreSQL 컨테이너: 18 계열 Alpine
- Redis 컨테이너: 8 계열 Alpine

Prisma 8은 신규 계약 기반 흐름으로 전환된 직후이므로 이번 기반 구성에서는 완전 지원 중인 Prisma 7.10.0을 사용한다.

## 3. 상태 확인

| 경로 | 목적 | 정상 응답 |
|---|---|---|
| `GET /api/health` | Next.js 프로세스 liveness | HTTP 200 |
| `GET /api/v1/health/live` | NestJS 프로세스 liveness | HTTP 200 |
| `GET /api/v1/health/ready` | PostgreSQL·Redis·오브젝트 저장소 TCP 도달성 | 모두 연결되면 HTTP 200, 아니면 503 |

현재 readiness는 첫 단계 구현으로 TCP 도달성만 검사한다. 데이터베이스 인증 쿼리, Redis 명령, S3 버킷 접근 권한 검사는 각 클라이언트를 API에 연결할 때 추가한다.

## 4. 보안 기본값

- PostgreSQL, Redis, MinIO, 웹, API 포트를 로컬 루프백 주소에만 게시
- 웹과 API 컨테이너를 비루트 사용자로 실행
- API CORS 허용 출처를 `WEB_ORIGIN` 하나로 제한
- Helmet과 전역 입력 검증 파이프 적용
- Next.js의 `X-Powered-By` 제거 및 클릭재킹·MIME 스니핑·권한 정책 헤더 적용
- Docker 내부 백엔드 네트워크를 외부 연결 불가로 분리
- `.env`와 생성된 Prisma 클라이언트를 Git 제외
- 로컬 예제 자격증명은 운영에서 사용할 수 없음을 명시
- MinIO 버킷의 익명 접근 차단

## 5. 실행 방법

```powershell
Copy-Item .env.example .env
npm.cmd install
docker compose up -d postgres redis minio minio-init
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run dev
```

Docker Desktop을 설치하고 PostgreSQL·Redis·MinIO·API·웹 전체 컨테이너를 실제로 기동해 검증했다. 설치 이유, 구성 요소별 역할, 호환성 수정과 검증 결과는 [Docker 설치 및 전체 스택 검증](./06_Docker_설치_및_전체스택_검증.md)에 기록했다.

## 7. 의존성 감사

불필요한 `@nestjs/mau` 개발 도구를 제거하여 감사 결과를 9건에서 4건으로 줄였다. 남은 4건은 Prisma CLI가 고정한 `deepmerge-ts`와 사용하지 않는 MySQL 드라이버 `mysql2`의 전이 취약점이다.

- 애플리케이션 요청 처리 코드가 이 두 패키지를 호출하지 않는다.
- API 런타임 Docker 단계는 API 운영 의존성만 별도로 설치하여 Prisma CLI를 포함하지 않는다.
- `npm audit fix --force`는 Prisma 6으로 강제 하향하여 Node.js 24 및 현재 스키마 구성과의 호환성을 훼손하므로 적용하지 않았다.
- Prisma 7의 수정 릴리스가 제공되면 잠금 파일을 갱신하고 감사를 다시 실행한다.

## 8. 롤백과 복구

- 애플리케이션 기반을 되돌릴 때 `apps`, `packages`, `infrastructure`, 루트 npm·Docker 설정을 함께 이전 커밋으로 복원한다.
- 데이터 컨테이너를 재생성해도 명명된 볼륨은 유지된다.
- 로컬 데이터를 완전히 지우는 `docker compose down --volumes`는 명시적인 데이터 폐기 작업에서만 사용한다.
- Prisma 스키마 변경은 생성된 SQL을 검토한 뒤 마이그레이션하며 운영에서 임의 reset을 사용하지 않는다.
