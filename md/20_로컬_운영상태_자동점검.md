# 로컬 운영 상태 자동 점검

## 목적과 역할

웹 화면이 열려도 데이터베이스 연결이나 사진 검사 서버, 모니터링 수집이 실패할 수 있다. `ops:check`는 이런 상태를 한 번에 확인하는 수동 실행 점검 명령이다. 상시 감시는 기존 Prometheus와 Alertmanager가 담당한다.

- PostgreSQL: 계정·매물·문의 등 원본 데이터 저장
- Redis: 로그인 세션 등 빠르게 확인해야 하는 정보 관리
- MinIO: 업로드 사진 저장
- ClamAV: 업로드 파일 악성코드 검사
- Prometheus: 서버 상태 지표 수집과 경보 조건 평가
- Alertmanager: 경보를 모아 관리. 현재 외부 수신 채널 없이 로컬 확인만 사용

## 실행

프로젝트 루트에서 실행한다. 기존 서버가 실행 중이어야 하며 이 명령은 서버를 시작·재시작하지 않는다.

```powershell
npm.cmd run ops:check
npm.cmd run test:operations
npm.cmd run test:external-readiness
```

`ops:check`는 `.env`의 `WEB_PORT`, `API_PORT`, `PROMETHEUS_PORT`, `ALERTMANAGER_PORT`를 읽는다. 동일한 프로세스 환경변수가 있으면 그 값을 우선한다. 생략 시 각각 3000·4000·9090·9093이다. 포트는 1~65535 정수만 허용한다.

출력의 `status: "ok"`는 아래 10개 검사가 해당 실행 시점에 통과했음을 뜻한다. 실패하면 `needs_attention`, 해당 항목의 간단한 설명, 종료 코드 1을 반환한다. 설정 오류도 종료 코드 1이다. 요청별 제한 시간은 8초이며 검사들은 동시에 실행한다.

## 검사 범위

| 항목 | 통과 조건 |
| --- | --- |
| 웹 | 웹 건강 확인 응답의 서비스와 상태 정상 |
| API | API liveness 응답의 서비스와 상태 정상 |
| 의존 서비스 | API readiness에서 PostgreSQL·Redis·MinIO·ClamAV 모두 up |
| 수집 지표 보호 | 토큰 없는 수집 지표 요청에 401 |
| 관리자 지표 보호 | 로그인 없는 관리자 지표 요청에 401 |
| Prometheus | 준비 상태 HTTP 200 |
| 실제 지표 수집 | API 수집 대상 존재, 모두 up, 최근 2분 내 수집 |
| 경보 규칙 | 사진 정리 실패·지연·장시간 실행 규칙 3개 존재, 최근 2분 내 평가 성공, 모두 inactive |
| 경보 수신 설정 | Prometheus의 활성 수신 대상에 내부 Alertmanager 존재 |
| Alertmanager | 준비 상태 HTTP 200 |

경보가 `pending` 또는 `firing`이면 확인이 필요한 상태로 처리한다. 서버를 방금 켜면 첫 수집·규칙 평가가 끝나기 전까지 실패할 수 있다. 이 경우 약 30초 후 다시 실행한다.

## 실패 시 확인 순서

1. `npm.cmd run docker:ps`로 관련 컨테이너 실행 상태를 확인한다.
2. 웹·API 연결 실패는 실행 상태와 `.env` 포트를 확인한다. 의존 서비스 실패는 API readiness 응답과 해당 서버 로그를 확인한다.
3. API는 정상인데 수집만 실패하면 Prometheus의 대상 상태 및 토큰 설정 일치 여부를 확인한다. 토큰 값은 출력하거나 작업 기록에 복사하지 않는다.
4. 경보 규칙 실패는 Prometheus에서 규칙 이름과 상태를 확인하고, 사진 정리 작업의 최근 성공 시각·오류를 조사한다. 통과시키기 위해 경보를 끄지 않는다.
5. 관리자·수집 지표 보호가 실패하면 공유 배포를 보류하고 인증 검사를 확인한다.

진단 중 데이터 볼륨 삭제, 무조건적인 재시작, 원본 DB 덮어쓰기를 수행하지 않는다.

## 안전 범위와 한계

- 요청 목적지는 `127.0.0.1`로 고정하고 HTTP 리다이렉트를 거부한다. 임의 외부 URL 옵션은 제공하지 않는다.
- GET 요청만 사용하며 로그인·매물 생성·사진 업로드·테스트 경보 발송을 수행하지 않는다. 서버 접근 로그나 요청 집계는 증가할 수 있다.
- 비밀번호·세션·메트릭 토큰을 요청에 넣지 않는다. 지표 수집 성공 여부는 이미 인증하여 수집 중인 Prometheus의 상태로 확인한다.
- 원문 응답·예외 메시지·환경변수 값을 결과에 출력하지 않는다.
- API readiness의 ClamAV 통과는 연결 가능 여부다. 실제 파일 검사 정확성이나 업로드 전체 흐름 통과를 의미하지 않는다.
- 경보 수신 설정과 서버 준비 상태만 검사하며 실제 경보 전달·외부 알림 수신까지 입증하지 않는다.
- 기존 지도 CDN·지도 타일 등의 외부 요청 여부는 이 점검 범위 밖이다. 주소 지오코딩과 외부 경보 승인 상태는 별도 `test:external-readiness`로 확인한다.
- 백업 복원, 성능 부하, 실기기 터치, 외부 HTTPS·도메인·메일 발송은 별도 검증이 필요하다. 이 결과만으로 운영 공개 준비 완료를 선언하지 않는다.

## 검증 결과

2026-09-05 18:27:14 KST 기준 로컬 서버 10개 항목 모두 통과했다. 점검 도구 회귀 테스트 15개도 통과했다. 의존 서비스 누락, 지표 수집 중단·지연, 경보 누락·발생·평가 실패, 비인증 지표 노출, 잘못된 응답·시간 초과, 잘못된 포트 입력 등을 모의 응답으로 검증했다. 실제 서버를 중단하는 장애 훈련은 하지 않았다.

외부 연결 사전 점검에서도 주소 지오코딩 승인 보류 및 외부 경보 수신 채널 미설정을 확인했다.

## 변경과 복구

`scripts/operations-check.mjs`, `scripts/operations-check.test.mjs`, 루트 `package.json`의 명령 2개를 추가했다. 신규 의존성 설치와 앱 재빌드는 필요 없다. 복구 시 이번 스크립트와 명령 추가만 제거하면 되며 서버·DB 변경은 없다.

후속 작업으로 [격리 HTTP 장애 감지·복구 훈련](./21_격리_HTTP_장애감지_복구훈련.md)을 추가했다. `npm.cmd run test:operations:drill`로 모의 서버의 연결 중단과 복구를 검증할 수 있다. 현재 사용자 작업용 서버를 임의로 중단하지 않는다. 실제 외부 배포에는 배포 대상과 도메인 등 사용자 결정이 별도로 필요하다.
