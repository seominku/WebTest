# ClamAV 비동기 이미지 검사 및 썸네일

## 완료 결과

업로드 응답을 기다리는 동안 무거운 악성코드 검사와 이미지 변환을 수행하지 않는다. API는 실제 파일 형식을 빠르게 확인한 원본을 MinIO 격리 경로에 저장하고 `UPLOADED` 상태로 응답한다. 백그라운드 처리기가 ClamAV 검사, 이미지 안전성·해상도 검사, WebP 원본과 640×400 썸네일 생성을 마친 뒤에만 `READY`로 바꾼다. 문제가 있는 파일은 `REJECTED`와 거부 사유로 남기며 공개 경로에서는 절대 제공하지 않는다.

## 구성 요소와 필요한 이유

| 구성 요소 | 역할 | 필요한 이유 |
| --- | --- | --- |
| ClamAV `clamd` | TCP 3310의 `INSTREAM` 명령으로 파일 바이트를 악성코드 서명과 비교 | 이미지 디코더만으로 잡을 수 없는 알려진 악성 파일을 공개 전에 차단하기 위해 필요 |
| 격리 객체 | `quarantine.{ext}` 키에 아직 신뢰하지 않은 원본 저장 | 검사 전 파일이 공개 이미지 주소에 연결되는 일을 막기 위해 필요 |
| 비동기 처리기 | 2초 간격으로 `UPLOADED`를 원자적으로 `SCANNING`으로 선점 | 업로드 응답 지연을 줄이고 여러 API 인스턴스가 같은 파일을 동시에 처리하지 않게 하기 위해 필요 |
| `sharp` 재인코딩 | 방향 보정, 4천만 픽셀 제한, 최소 640×480 확인, 품질 85 WebP 생성 | 손상 파일·픽셀 폭탄을 거부하고 원본 메타데이터나 불필요한 데이터를 제거하기 위해 필요 |
| 640×400 썸네일 | 품질 75 WebP의 목록용 파생 이미지 생성 | 목록 카드마다 큰 원본을 내려받는 낭비를 줄여 표시 속도와 전송 비용을 개선하기 위해 필요 |
| 상태 폴링 UI | `검사 대기`, `악성코드 검사 중`, `준비 완료`, `거부` 표시 | 사용자가 업로드 성공과 최종 공개 가능 상태를 혼동하지 않게 하기 위해 필요 |
| 이력·감사 로그 | 준비 완료와 거부 사건, 검사 결과를 별도 기록 | 장애·보안 조사에서 어떤 파일이 언제 처리됐는지 추적하기 위해 필요 |

ClamAV 공식 컨테이너는 바이러스 서명 데이터베이스를 `/var/lib/clamav`에 보존하고 자체 `clamd` 건강 검사를 제공한다. 이 프로젝트는 해당 디렉터리에 Docker 볼륨을 연결하여 컨테이너 재생성 때마다 전체 서명을 다시 받는 일을 줄였다. 공식 문서는 ClamAV에 최소 약 3GiB, 권장 4GiB RAM을 안내하므로 Docker Desktop 메모리도 이에 맞게 확보해야 한다.

- 공식 설치 문서: <https://docs.clamav.net/manual/Installing/Docker.html>
- 공식 Docker 이미지: <https://hub.docker.com/r/clamav/clamav/>

## 상태와 저장 흐름

1. 브라우저가 JPEG·PNG·WebP 파일과 현재 매물 버전을 전송한다.
2. API가 10MB 제한과 파일 바이트 서명을 확인하고 `quarantine` 객체를 저장한다.
3. DB에 이미지 상태 `UPLOADED`를 기록하고 즉시 응답한다.
4. 처리기가 조건부 갱신으로 한 건을 `SCANNING`으로 선점한다.
5. ClamAV가 원본 전체를 검사한다.
6. 안전하면 `sharp`가 디코딩·해상도 확인 후 `full.webp`와 `thumbnail.webp`를 만든다.
7. DB 트랜잭션이 두 객체 키, 크기, 해상도, `READY`, 이력과 감사 로그를 기록한다.
8. 성공 후 격리 원본을 삭제한다. 알려진 악성코드 또는 이미지 정책 위반이면 격리 원본을 삭제하고 `REJECTED` 사유를 기록한다.
9. 저장소·ClamAV 같은 일시적 장애는 시도 횟수를 늘리고 지수 백오프 후 재시도한다. 5회 실패하면 `REJECTED`로 격리한다.

## 공개·권한 정책

- 소유 중개사도 `READY`가 되기 전에는 이미지 바이트를 받을 수 없다.
- 공개 목록은 작은 썸네일만 사용한다.
- 공개 상세 갤러리는 WebP 원본을 사용한다.
- 매물이 `PUBLISHED`이고 게시 기간이 남은 경우에만 공개 이미지 API가 응답한다.
- `REJECTED`, `UPLOADED`, `SCANNING` 이미지는 검수용 정상 이미지 수와 공개 이미지 수에서 제외한다.
- 이미지 삭제 시 원본과 썸네일 객체를 모두 정리한다.
- 여러 장 업로드 시 서버 응답 기준으로 현재 파일 번호와 전체 개수를 표시한다.
- 매일 한 번 DB 참조 목록과 MinIO 객체 목록을 비교해 24시간 지난 고아 객체를 정리한다.
- 관리자 전용 메트릭 API에서 마지막 실행·삭제 수·오류를 확인한다.

## API

- `POST /api/v1/listings/mine/:id/images`: 격리 업로드 및 검사 대기 등록
- `GET /api/v1/listings/mine/:id/images/:imageId/content`: 소유 중개사용 READY 원본
- `GET /api/v1/listings/mine/:id/images/:imageId/thumbnail`: 소유 중개사용 READY 썸네일
- `GET /api/v1/listings/:id/images/:imageId/content`: 게시 중인 READY 원본
- `GET /api/v1/listings/:id/images/:imageId/thumbnail`: 게시 중인 READY 썸네일

## 운영과 복구

- readiness에 `malware-scanner`를 포함하여 ClamAV 연결 실패를 배포 전에 확인한다.
- 재시작 뒤 남은 `UPLOADED` 파일은 자동으로 다시 처리된다.
- `SCANNING` 작업에는 처리 시작 시각을 기록하며, 10분 이상 멈춘 작업은 다음 처리 주기에 `UPLOADED`로 되돌려 자동 재시도한다.
- 롤백 시 API 코드와 DB 마이그레이션을 함께 되돌려야 한다. 이미 생성한 `thumbnail.webp` 객체는 기능상 무해하지만 별도 고아 객체 정리 작업이 필요하다.

## 검증 범위

- 정상 PNG: `UPLOADED → SCANNING → READY`
- EICAR 표준 테스트 문자열: ClamAV 실제 탐지
- 최소 해상도 미달 이미지: 비동기 `REJECTED`와 사유 기록
- 원본 WebP와 640×400 썸네일 생성·조회
- 초안 타인 접근과 공개 접근 차단
- 게시 후 공개 썸네일·원본 제공, 게시 중지 후 차단
- 준비 완료·거부 이력과 감사 로그 생성
- ClamAV 포함 Docker 서비스 건강 상태 확인
