# 외부 서비스 연결 준비 체크리스트

## 현재 상태

- 주소 지오코딩: 비활성화. 공급자 URL을 입력해도 `GEOCODING_DATA_SHARING_APPROVED=true`가 아니면 요청하지 않는다.
- 외부 알림 전송: 비활성화. Alertmanager는 `local-observer` 수신처만 사용한다.
- `npm.cmd run test:external-readiness`는 설정 파일만 읽으며 네트워크 요청을 만들지 않는다.

## 주소 지오코딩을 켜기 전

1. 외부로 전달되는 값이 도로명주소와 우편번호임을 개인정보 처리방침과 등록 화면에 안내한다.
2. 공급자의 이용약관, 국내 주소 처리 위치, 보관 기간, 재사용 여부를 검토한다.
3. 운영 트래픽에 맞는 호출량 제한과 장애 시 수동 좌표 입력 절차를 정한다.
4. 자체 호스팅 또는 승인된 공급자의 HTTPS 주소를 `GEOCODING_BASE_URL`에 설정한다.
5. 담당자가 전송 범위를 최종 확인한 뒤에만 `GEOCODING_DATA_SHARING_APPROVED=true`로 바꾼다.
6. 준비 상태 검사와 통합 테스트를 통과한 뒤 배포한다.

## 외부 경보 수신처를 켜기 전

1. 전달될 경보 이름, 심각도, 서비스 상태에 고객 개인정보가 포함되지 않는지 확인한다.
2. 이메일·Slack·웹훅 등의 수신 계정, 보관 정책, 접근 권한을 승인한다.
3. Alertmanager 설정에 승인된 수신처만 추가한다.
4. `EXTERNAL_ALERT_DELIVERY_APPROVED=true`를 명시하고 준비 상태 검사를 실행한다.
5. 개인정보나 주소가 경보 레이블·설명에 들어가지 않는 회귀 검사를 수행한다.

## 중지와 복구

- 지오코딩은 승인 플래그를 `false`로 되돌리면 공급자 URL이 남아 있어도 즉시 차단된다.
- 외부 경보는 Alertmanager의 외부 수신처를 제거하고 `local-observer`로 되돌린다.
- 전송이 의심되면 공급자 로그와 애플리케이션 감사 로그를 확인하고 관련 자격 증명을 교체한다.
