# 매물 게시 수명주기 및 자동 만료

## 작업 결과

검수 승인된 매물을 관리자가 기간을 지정해 게시하고, 소유 중개사가 일시 중지·재개·거래 완료하는 수명주기를 구현했다. 게시 종료 시각이 지나면 API 시작 시와 1분 간격으로 자동 만료 처리하며, 모든 상태 변경에 버전·상태 이력·감사 로그를 남긴다.

## 구성 요소의 역할과 필요한 이유

| 구성 요소 | 역할 | 필요한 이유 |
|---|---|---|
| 게시 대기열 | `APPROVED` 매물을 관리자에게 제공 | 검수 통과와 실제 공개를 분리해 게시 시점을 통제하기 위해 필요 |
| 게시 기간 | 관리자가 1~365일의 노출 기간 지정 | 오래된 매물이 무기한 공개되는 일을 막기 위해 필요 |
| 게시 API | `APPROVED`를 `PUBLISHED`로 바꾸고 게시·만료 시각 기록 | 공개 조건을 통과하는 시점을 명확히 기록하기 위해 필요 |
| 일시 중지 | `PUBLISHED`를 `PAUSED`로 전환 | 거래 협의나 정보 확인 중 일시적으로 검색 노출을 막기 위해 필요 |
| 게시 재개 | 만료되지 않은 `PAUSED`를 다시 `PUBLISHED`로 전환 | 기존 게시 기간을 유지하면서 노출을 복원하기 위해 필요 |
| 거래 완료 | 공개 또는 중지 매물을 `COMPLETED`로 종료 | 계약이 끝난 매물이 계속 문의를 받는 것을 막기 위해 필요 |
| 자동 만료 서비스 | API 시작 시와 1분마다 종료 시각이 지난 공개·중지 매물을 `EXPIRED` 처리 | 운영자가 수동으로 내리지 않아도 공개 기한을 보장하기 위해 필요 |
| 조건부 갱신 | 상태와 버전이 일치할 때만 만료·전환 | 여러 API 인스턴스가 동시에 검사해도 이력과 상태 변경이 중복되지 않게 하기 위해 필요 |
| 공개 조회 조건 | `PUBLISHED`이면서 만료 전인 데이터만 응답 | 상태 정리 작업 직전에도 만료된 매물이 노출되지 않게 하는 이중 안전장치 |
| 상태 이력·감사 로그 | 이전·다음 상태, 버전, 기간과 행위자 기록 | 게시 운영 및 장애·분쟁 조사에 필요 |

## 상태 흐름

- 관리자: `APPROVED → PUBLISHED`
- 중개사: `PUBLISHED → PAUSED`
- 중개사: `PAUSED → PUBLISHED` 단, 만료 전
- 중개사: `PUBLISHED 또는 PAUSED → COMPLETED`
- 시스템: 만료 시각이 지난 `PUBLISHED 또는 PAUSED → EXPIRED`

상태·역할·소유권·버전 중 하나라도 맞지 않으면 전환을 거절한다.

## API와 화면

- `GET /api/v1/listings/publication-queue`: 관리자 게시 대기열
- `POST /api/v1/listings/:id/publish`: 게시 시작과 기간 설정
- `POST /api/v1/listings/:id/pause`: 중개사 게시 중지
- `POST /api/v1/listings/:id/resume`: 중개사 게시 재개
- `POST /api/v1/listings/:id/complete`: 중개사 거래 완료
- `/admin/listings`: 승인 매물의 게시 기간 선택과 게시 시작
- `/agent/listings`: 게시 만료일, 일시 중지·재개·거래 완료 버튼

## 검증 결과

- 중개사의 관리자 게시 API 접근 `403`
- 관리자 30일 게시와 게시·만료 시각 저장 확인
- 게시 직후 공개 상세 `200`
- 일시 중지 후 공개 상세 `404`
- 재개 후 공개 상세 `200`
- 거래 완료 후 공개 상세 `404`
- 만료 시각 경과 후 시스템 자동 만료와 버전 증가 확인
- 전체 상태 이력 13건, 감사 로그 13건 확인
- 기존 검수 기록·가격 이력 유지 확인
